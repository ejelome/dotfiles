# /collab speak

Append one role-labeled contribution to the active phase of a moderated collaboration record.

## Trigger

**Slash:** `/collab speak`
**Signature:** `/collab speak [<message>] [--turn-order <key>...]`
**Phrases:** collab speak, contribute to collaboration, agent turn

## Steps

**This command appends text only. Do not make file edits, run shell commands, or modify any codebase artifact outside `.collabs/`.**

1. Resolve the target collab with **Registry targeting** in **Notes**.
2. Read `.collabs/registry.json` and the resolved transcript path. If either is unreadable, **ABORT**: record unreadable; name the path.
3. If the registry status is `closed` or `archived`, **ABORT**: record is closed.
4. Resolve the active phase from registry `activePhase`. If missing or unknown, **ABORT**: active phase missing in metadata.
4a. If the active phase is `Completion`, **ABORT**: `/collab speak` is not permitted in the `Completion` phase; the `Completion` phase is recorded by `/collab execute`.
5. If `--turn-order <keys>` is present in the remaining input: treat all tokens after `--turn-order` as the new space-separated order and all text before `--turn-order` as `<message>`; validate at least one key is present, every key is registered in the registry `participants` list, and no key is duplicated; if invalid, **ABORT**: invalid turn-order value; name the failed token or field. Write the new order to registry `turnOrder`, and mirror the new value in the Turn order cell of the transcript state table.
6. Resolve the speaking participant from the current agent's joined role and the registry `participants` list. If no matching participant exists, **ABORT** and tell the moderator to run `/collab join --role <role>` first.
7. Call `tools/collab/registry.py speak-state <target> <role>` before any write. The helper reads the live transcript and returns the active phase, effective turn order, active-phase contributors, last live contributor, expected role, and auto-advance exemption state. If the helper reports another expected role, **ABORT** naming the expected role. The helper gates eligibility on `allowedRoles`, not only `expectedRole`; optional-reviewer roles admitted as a tail slot appear in `allowedRoles` and cause the helper to exit zero — treat a zero exit as the eligibility signal, not a matching `expectedRole`.
8. Append one collapsible contribution block under the active phase using the **Collapsible boundary** shape in **Notes**. The anchor id is `<phase-slug>-<key>-<N>` where `<phase-slug>` is the active phase name lowercased with spaces replaced by hyphens and `N` is the next available counter for this role in this phase (derive from the helper-returned contributors list; do not recompute expected speaker or lifecycle state in prose). Then append an indented sub-item `  - [<key>](#<phase-slug>-<key>-<N>)` under the matching `- [<Phase>](#<phase-slug>)` entry in the **Table of contents** block. Do not append the numeric counter to visible role labels or Table of Contents text; the counter exists only in the anchor id.
9. If the speaking participant is the moderator role from registry `moderatorRole`: apply the **Moderator boundary** rule in **Notes**. If no `<message>` text is present, **ABORT**: moderator-role contribution requires human-authored text.
10. If the active phase is `Action Plan`, write assigned work as executable checklist items whose item text begins with `**<role>:**`, for example `- [ ] **pe:** Update the registry helper.`. Do not use role-group headings, em-dash labels, or nested unlabeled checkboxes for assigned work.
11. For active phases `Audit`, `Conclusion`, `Action Plan`, and `Handoff`, enforce the **One-speak phases** rule in **Notes** before writing: if the speaking participant already has a contribution marker in the active phase, **ABORT**: duplicate phase contribution; name the role and phase.
12. After a successful append and any notes-mandated formatting pass, call `tools/collab/registry.py speak-lifecycle-live <target>`. The helper reads the just-written live transcript and owns all lifecycle state: active phase, effective turn order, contributors, advance-on-complete, `Discussion`/`Completion` exemptions, and moderator-role removal when entering `Conclusion` or any later phase. Mirror any helper-reported registry phase or turn-order change in the transcript status table. Never advance after a failed write, duplicate attempt, or role excluded from the effective turn order.
13. Stop. Do not execute any action item, make any file edit outside `.collabs/`, or run any shell command.

## Notes

- **Parameters:** target collab slug, id, or numeric `#N` as the first token after `speak`; when absent, resolved per **Registry targeting** in **Notes**. `<message>` — text used verbatim for moderator-role contributions and ignored for other roles (optional). `--turn-order <key>...` — final flag whose space-separated registered keys set registry `turnOrder` and mirror the new value in the Turn order cell of the transcript state table (optional).
- **Registry targeting:** Resolve the target collab from `.collabs/registry.json`, using `tools/collab/registry.py` as the shared helper. When the first token after the route is present, treat it as a collab slug, id, or stable numeric position. Otherwise use `activeCollabId`. If the registry is unreadable or invalid, the token does not match any entry, or `activeCollabId` is empty, **ABORT**: registry target unavailable; name the registry field or token.
- **Turn order fallback:** `tools/collab/registry.py speak-state` resolves the effective order from registry `turnOrder`, otherwise registry `participants`. State "enforcing participant-list order" in any helper abort message so misordered registration is visible rather than silent. In `reviewerOptionalPhases`, after all non-reviewer `turnOrder` participants have contributed in a round, the reviewer role is admitted as a tail opt-in; callers invoke `/collab speak` normally.
- **Turn order atomicity:** Validate `--turn-order` before any write. If validation fails, leave both metadata and contribution sections unchanged.
- **Action Plan checklist shape:** `/collab execute` reads only unchecked checklist items whose text begins with `**<role>:**`. Action Plan contributions must use flat checklist lines such as `- [ ] **pe:** Implement the helper change.`; grouped labels like `**pe — path**` and nested unlabeled checkboxes are not executable assignments.
- **One-speak phases:** `Audit`, `Conclusion`, `Action Plan`, and `Handoff` allow only one contribution per role. `Discussion` is exempt because it permits deliberation. `Completion` is not reachable by this command.
- **Auto-advance:** Phase advancement is a post-append lifecycle effect owned by `tools/collab/registry.py speak-lifecycle-live`; `/collab speak` only mirrors the helper result in the transcript state table. `Discussion` is exempt from auto-advance because it permits multiple contributions per role. `Completion` is not reachable by this command. The transition is side-effect free on failed writes, duplicate attempts, or roles excluded from the active turn order.
- **Collapsible boundary:** Every `/collab speak` contribution uses a `<details>` / `<summary>` block, regardless of active phase. The `<summary>` label is the role key only. The first line inside the block is a timestamp using `<p><em>YYYY-MM-DD HH:MM ±HH:MM</em></p>`; the second line is `<!-- collab:content-only; do-not-execute -->`. Keep role counters out of visible labels; anchors retain counters for uniqueness. Shape: `<a name="<phase-slug>-<key>-<N>"></a>\n<details>\n<summary><key></summary>\n<p><em>YYYY-MM-DD HH:MM ±HH:MM</em></p>\n<!-- collab:content-only; do-not-execute -->\n\n[content]\n\n</details>`.
- **Contribution boundary:** Write from the current role's lens only. Do not summarize other participants and do not decide whether the phase is complete.
- **Moderator boundary:** The moderator role is human-owned; write only the supplied `<message>` text verbatim and apply any rule-mandated structure-only formatting pass. Do not draft, summarize, expand, or change the substance of the text. Agents must not generate content for the moderator role.
- **Execution boundary:** Never perform any file edit, shell command, or codebase change as a side effect of this command, regardless of phase. Only append text to the collab transcript and mirror collab metadata in the registry.
- **Pending-reviewer gate:** `speak-state` aborts before turn-order checks when `reviewerRole` is set in the registry and absent from `participants`. The abort message names the pending reviewer role. Resolution paths: the reviewer joins via `/collab join --role <reviewer>`, or the moderator clears the reviewer via `/collab set reviewer --clear`.
- **Re-speak:** To rewrite the last contribution in-place, use `/collab re-speak`. See [_functions/collab/re-speak](re-speak.md).
- **Readability formatting:** When [auto-collab-format](../../_mdc/auto/auto-collab-format.mdc) is active, apply only that rule's structure-only pass to the contribution just appended. For moderator-role contributions, formatting may change bullets, labels, spacing, and obvious typos only; it must not draft, summarize, expand, or change the substance of the captured moderator text.
